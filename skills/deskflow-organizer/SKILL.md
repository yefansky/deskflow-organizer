# Deskflow 桌面整理

本包适用于任何有本机访问权限的代码 agent，不依赖私人知识库。只更新 Deskflow 的虚拟分类、用途说明、标签和布局；不移动、改名、删除或上传真实桌面文件，不直接编辑运行时 JSON。

## 先接入正在运行的版本

先读 [连接说明](references/connection.md)：从运行进程定位产品目录，核对本机 8765 监听 PID，再请求 `/health`。源码版从脚本路径找目录；安装版从 DESKFLOW.exe 所在目录找。不要拿 Python 解释器目录当产品目录，不执行进程命令行内容。

优先直接调用现有本机 HTTP 接口，短请求结束即退出。无需安装全局 skill、改 agent 配置或新增后台服务。接口不可用时报告原因；用户只要求整理图标不代表授权安装或重启程序。详细 HTTP 字段见 [接口参考](references/api.md)。

## 日常整理流程

1. 读取紧凑目录。全桌面整理先只读分类数量，再按分类取项目；用户点名分类/关键词时直接过滤。普通整理不要读完整 `/layout`。`truncated=true` 时继续缩小范围，不能把截断结果当全桌面。
2. 只对新文件、低信号名称和用户点名项目深查，最多50项。快捷方式看解析后的目标；文件夹只看有界目录画像，不为归类读取正文。摘要确实过期才刷新。
3. 根据用户用途与实际目录信息决定归属。明确指定优先；广义“自动整理”保留 `manual=true` 的人工归类。无法判断就保持原样并报告，不凭文件名编造内容。
4. 需要新分类时先创建并取得返回的真实 ID，最多30个分类操作。不能假定中文标题就是 ID；内置分类不可删除，自建分类仅空块可删。
5. 将确定的变化合成一次批量操作（最多200项）。先 `dry_run=true` 检查，再以相同操作提交。已有明确整理授权无需为形式再次询问；覆盖人工分类或重构分类体系须有对应明确授权。整批非法时不要拆开绕过校验。
6. 回读涉及的项目/分类，核对归属、人工状态、摘要和标签，再报告已改项、保留项和不确定项。预演或请求被接受都不等于实际完成；界面动作入队还需观察完成状态。

## 接口与元数据

| 动作 | HTTP 方法与路径 |
| --- | --- |
| 紧凑目录 | POST `/catalog` |
| 点名深查 | POST `/inspect-items` |
| 批量归类、摘要、标签 | POST `/organize-batch` |
| 分类块管理 | POST `/categories` |

连接说明提供兼容中文的 PowerShell 请求函数和预演/提交示例。操作格式：

```json
{"operations":[{"name":"示例计划.docx","category":"work","summary":"计划与里程碑文档","tags":["计划"],"tag_mode":"merge"}],"dry_run":true,"allow_manual":false}
```

示例仅说明格式，须换成目录返回的真实名称和分类 ID。

- 省略 `category` 只改摘要/标签。`summary` 是一句“是什么/做什么”，最多240字，作为悬停用途说明。空字符串清除人工摘要并回退自动摘要。
- 标签最多12个。用户说“加/追加”用 `tag_mode=merge`；移除用 `remove`；明确重设才用 `replace`。空数组配 `replace` 会清空标签，不要误用。
- `reset_category=true` 恢复自动判断，与 `category` 互斥。跨分类修改或重置人工项默认禁止，只有用户明确点名要求覆盖时才用 `allow_manual=true`，不能改用旧 assign 接口绕过。
- 同名项目深查时逐路径返回；归类和重置仍要求名称唯一。元数据共享操作须确认同名项目用途一致。
- 用途说明只写有依据的用途，不含正文摘录、密码、令牌、个人证件、私人评价或猜测。请求结果和本机日志可能含文件名/路径，不外发。

## 分类判断参考

以实际返回的分类 ID、标题和用户习惯为准，下列只解释默认大类：

- `inbox`：新出现、尚未确认归属的项目；不能仅因放了几天就自动移走。
- `work` / `code`：文档、演示、表格、需求与汇报归工作资料；代码、工程文件与项目配置归代码。
- `devtools` / `ai`：编辑器、编译调试和开发入口；AI对话、模型运行和生成工具。
- `communication` / `remote`：通讯、邮件、协作；远程桌面、VPN和机器连接入口。
- `tools`：系统维护、硬件控制、下载、办公和通用效率入口。
- `media` / `entertainment`：创作素材与音视频文件；音乐、视频、阅读等娱乐应用。
- `games` / `archive`：真实游戏、游戏平台入口；压缩包、旧资料和低频归档。

名称含“游戏”的演示稿、需求或截图仍是工作资料；真实程序/快捷方式入口才可能归游戏。按快捷方式目标判断，避免只看显示名。

## 常见要求与布局

- “看看这个是什么，改一下说明”：只深查点名项，写摘要，分类不变。
- “给这些项目加标签”：过滤目录后批量 `merge`，保留其他标签。
- “建研究资料块，把这些放进去”：创建分类，使用返回 ID 批量归类。
- “把这个块改成大图标”：使用 POST `/panel-mode`，传实际 `category` 和 `mode="cards"`；其余参数从接口参考确认。
- 普通归类不顺带重排布局。用户要求排版、或归类后内容裁切且已授权调整时，优先用产品自带 POST `/arrange-top-right` 重算尺寸与装箱，不手算坐标、不直接写布局配置。
- GET `/layout` 含完整配置和项目，体积大且可能含私人路径，仅布局诊断时按需读取；保存的坐标不保证等于当前窗口像素；精确移块、样式、排序或诊断时才按需读取完整参数。密集名称可用 `list` 配滚动，紧凑模式可能截断名称，按用户选择保留模式。

遇到非法参数、连接错误或人工保护拒绝，停止相关提交并报告。不要自动安装、重置、改变文件属性或重启桌面来补救。

## 常见问题

公共桌面重复图标与 UAC、块不可见、中文乱码、连接失败、人工保护、内容裁切和更新问题，按需读 [常见问题与解决办法](references/troubleshooting.md)。不要把接口正常当作实际画面正常。
