# 常见问题与解决办法

先确认发生问题的那台机器、实际运行进程和版本。以下是操作与诊断方法，不代表每个现场问题都已修复。仅凭 `/health` 成功不能证明桌面画面正常。

## 公共桌面图标重复、隐藏失败：需要管理员同意 UAC

**表现**：项目已在整理块中，原生桌面仍有副本；个人图标正常，部分公共图标不消失。

1. 按需深查受影响项目，确认真实路径是否位于公共桌面（系统公共桌面通常为 `%PUBLIC%\Desktop`）。公共目录的权限与个人桌面不同，普通进程可能无法改变其图标隐藏属性。
2. 请用户在 Deskflow 托盘菜单选择 **“修复公共桌面重复图标（需要管理员确认）”**。
3. 由用户亲自在 Windows **UAC（用户账户控制）** 提示中同意；标准账户可能需要管理员凭据。agent不能代点同意、索取或记录管理员密码。
4. 该操作启动本次整理会话的受限属性助手，只处理公共桌面直接子项；不移动文件、不修改访问权限，退出整理器后恢复原属性。
5. 用户取消、无管理员凭据或企业策略禁止时，公共图标会保持可见，报告“权限未授权”，不能当作成功。下次重启整理会话需再次从菜单授权。

不需要把整个 Deskflow 或 agent 长期以管理员身份运行；不要改ACL、禁用UAC、删除公共快捷方式或隐藏整个公共桌面来解决重复。

## 拖入块后原生图标半透明残留

区分“虚拟分类保存”“隐藏属性修改成功”“Explorer视图移除”三个阶段。检查实际路径、是否公共桌面、用户是否选择显示受保护系统文件，再按上一节处理权限。回读 `/catalog` 只能验证分类，仍要看原生桌面实际画面。无法消失时记录版本和最小复现，按正常更新流程验证；不要全局重建图标缓存、伪造文件删除/创建通知或改Explorer隐藏偏好。

## 无法连接、端口被占用或选错版本

按 [连接说明](connection.md) 对照进程、脚本/EXE所在目录与8765监听PID。源码的Python解释器目录不是产品目录；安装目录 `scripts` 中的兼容文件也不是完整开发源码。多个目录并存时先辨认当前监听进程，不自动启动另一个版本。确认未运行后，请用户通过正常快捷方式或托盘启动；重启需有用户授权。不要为连接失败自动安装服务、开放端口或改agent配置。

## 中文乱码或请求参数报错

用连接说明中的 `Send-DeskflowJson` 显式按UTF-8发送和解析，兼容Windows PowerShell 5.1。`dry_run`、`allow_manual` 等传JSON布尔值，不传字符串。分类用实际ID，名称用目录返回原值。遇到400/422错误先核对字段；不要吞错后提交。分类同名项目存在歧义时不猜目标。

## 人工分类被保护，或整批整理被拒绝

`manual=true` 是用户习惯，广义自动整理应保留。拆出不需要覆盖人工习惯的操作重新预演；只有用户明确要求修改被点名人工项才使用 `allow_manual=true`。任何非法项都会导致整批拒绝，不要误报其他项已提交，也不能换单项接口绕过保护。

## 归类后块里显示不全、紧凑模式名称截断

先确认项目确实进入目标分类，检查块内滚动、模式和尺寸。用户授权排版时调用 `/arrange-top-right` 让产品按内容重算并装箱，随后检查画面；它会重排现有块，普通归类不自动执行。内容密集可选list配滚动；compact双列可能截断名称，按用户偏好选择。不要手改配置或写死每个块坐标。

## health正常但块不可见，或只剩常用块

检查是否刚双击桌面空白进入专注模式：再双击可恢复全部；没有爱心块时专注模式会隐藏全部。再检查目标显示器、远程连接前后屏数、块是否在可见工作区、是否被其他应用覆盖。先让用户打开管理器/设置检查，不删除布局或恢复默认。健康回包、窗口visible状态都不能代替用户看到的画面；久置、多屏和重连问题按现场记录，不能声称全部已解决。

## 管理器不在任务栏、点击入口似乎没反应

管理器默认驻留通知区域，先检查托盘。当前版桌面/开始菜单入口可显式唤出已有管理器，登录自启保持静默。确认运行目录与版本，必要时用正常更新流程；不要重复启动多个源码和安装实例。

## 从块里启动的程序报“不受信任的装入点”

先比较同一程序从开始菜单启动是否正常；若其数据目录跨盘用了junction（目录连接），可能是父进程继承的Windows重定向信任策略。获授权后正常退出Deskflow，再由用户从普通资源管理器/快捷方式重开，对照复验。不要从受限沙箱父进程重启，不删除目录连接背后的真实数据，不自行关闭系统安全策略或重建目录。仍失败时交给管理员核实进程策略和目录连接。

## 安装更新失败、修改源码没生效

安装版通过内置匿名HTTPS更新，无需GitHub登录或开发工具。下载失败先看网络/限流提示；SHA-256不一致时停止安装，不跳过校验。源码修改只影响运行该源码的进程，不能据此认为其他机器安装版已更新；源码模式使用Git同步，正式安装版使用Release安装包。升级保留分类和布局，故障时不要删用户配置补救。

## 日志似乎停在一行

同时检查同一PID日志及轮转分卷的更新时间和大小；单文件停止增长不证明卡死。日志可能包含文件名、真实路径和异常信息，属于本机私人材料；对外反馈只提供必要且脱敏的片段，不打包整个用户目录或桌面清单。
